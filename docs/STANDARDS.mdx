# Skill Steward — Agent Skills package standards

This is the package-format spec for installable Agent Skills in this repository. For the broader quality contract that applies to apps, libraries, tools, plugins, harnesses, and meta repos, see [repo-quality-contracts.mdx](repo-quality-contracts).

This document consolidates rules from the open ecosystem so skills in this repo install reliably via `npx skills` and appear on [skills.sh](https://skills.sh).

## Skill Cohesion and Boundaries

To prevent cognitive overload for agents and users, skills must adhere to the **Skill Cohesion** standard ([ADR 0016](decisions/0016-skill-cohesion-and-lifecycle-boundaries)):

1. **Lifecycle Journeys over Atomic Actions:** Skills must encapsulate complete lifecycles (e.g., authoring + reviewing). Avoid creating separate skills for two halves of the same process.
2. **Intent Overlap:** Group tools by the user's high-level goal, not by the specific files they touch. If two skills share the same intent (e.g., governing the doc lattice), merge them.
3. **Bundle Philosophy with Mechanics:** Abstract guidelines ("the why") must be bundled with the mechanical tools or linters ("the how") that enforce them. Do not create purely philosophical skills.

## Skill package structure

```
skill-name/
├── SKILL.md          # Required
├── references/       # Optional — docs loaded on demand
│   └── sources.md    # Required in skill_steward — curated URLs + changelog
├── scripts/          # Optional — executable helpers
├── assets/           # Optional — templates, images, data
└── LICENSE           # Optional — if not MIT at repo root
```

### Citations (skill_steward)

Every skill must include **`references/sources.md`** listing URLs for specs, papers, and reference repos used. Update when research changes. Skill: `skill-source-citations`.

### T-named skill quality gates ([ADR 0011](decisions/0011-tiered-skill-evals-and-rule-based-ci), [ADR 0027](decisions/0027-t-named-skill-quality-gates))

| Tier | Skills | Required |
|------|--------|----------|
| **T1 — Behavior-critical eval-gated** | `harness-engineering-lifecycle`, `mcp-harness-repo-maintainer`, `mixture-of-experts`, `multi-agent-handoff`, `plugin-marketplace-setup`, `repo-quality-system-lifecycle`, `repository-governance-lifecycle`, `skill-authoring-lifecycle`, `skill-eval-improve`, `steward-continuity-boundary-lifecycle`, `vision-alignment-foresight` | `references/evals.md` + ≥2 files in `evals/cases/*.yaml`; `pnpm run eval` passes |
| **T2 — Structural validate-only** | All other skills under `skills/` | `pnpm run validate`; optional `evals.md` when behavior-critical |

Case schema: [eval-case-schema.md](https://github.com/arenukvern/skill_steward/blob/main/skills/skill-eval-improve/references/eval-case-schema.md). Skill: `skill-eval-improve`.

## SKILL.md

### Frontmatter (YAML between `---` markers)

| Field | Required | Constraints |
|-------|----------|-------------|
| `name` | Yes | 1–64 chars; `a-z`, `0-9`, `-` only; no leading/trailing `-`; no `--`; **must match parent directory** |
| `description` | Yes | 1–1024 chars; what it does **and** when to use it |
| `license` | No | SPDX id or pointer to bundled license file |
| `type` | No | Skill Steward repo-local classification such as `governance`; portable agents may ignore it |
| `compatibility` | No | Max 500 chars; env / product requirements |
| `metadata` | No | String key-value map (`author`, `version`, `category`, `tags`) |
| `allowed-tools` | No | Experimental; space-separated tool list |
| `paths` | No | Agent-specific file scoping; Cursor supports top-level globs, other agents may ignore |
| `disable-model-invocation` | No | Agent-specific explicit-invocation control; Cursor/Zed support top-level, Codex uses `agents/openai.yaml` policy |

### Agent-specific activation controls (optional)

Use top-level fields only when the target agent documents them. Portable agents that do not support them should ignore them, but do not depend on that for safety-critical gating.

```yaml
paths:
  - "docs/**"
disable-model-invocation: true
```

| Field | Purpose | Placement |
|-------|---------|-----------|
| `paths` | Glob list — skill only surfaces for matching files in agents that support it | top-level |
| `disable-model-invocation` | `true` = user must invoke `/skill-name` manually in agents that support it | top-level |

### Codex `agents/openai.yaml` (optional)

Use `agents/openai.yaml` for Codex app UI metadata, invocation policy, and tool dependencies. Keep it optional so Skill Steward remains cross-agent.

```yaml
interface:
  display_name: "Skill Name"
  short_description: "One-line user-facing summary"
  default_prompt: "Use this skill to ..."
policy:
  allow_implicit_invocation: false
```

`allow_implicit_invocation: false` is the Codex equivalent of making a skill explicit-invocation only.

### Claude Code extensions (optional)

```yaml
metadata:
  claude:
    argument-hint: "options"
    user-invocable: false
```

| Field | Purpose | Nested Path |
|-------|---------|-------------|
| `argument-hint` | Autocomplete hint for `/skill` args | `metadata.claude.argument-hint` |
| `user-invocable` | `false` hides from `/` menu | `metadata.claude.user-invocable` |
| `context` | `fork` runs in isolated subagent | `metadata.claude.context` |

### Body (Markdown)

- No strict schema; write clear step-by-step instructions.
- Recommended: **&lt; 500 lines** in `SKILL.md`; split long content into `references/`.
- Progressive disclosure: metadata (~100 tokens) → full SKILL.md on activation → files on demand.

## Repository-local registration (team workflow)

This section is about installing Agent Skills into a repo. It is not the general repo-quality contract. For repo-level stewardship proof, use [repo-quality-contracts.mdx](repo-quality-contracts).


For teams and shared projects, Skill Steward supports **repo-local skill registration** using a standard configuration manifest in the root of the consumer project. This is a deterministic structure helper for agents and maintainers; public install/update distribution remains `npx skills`.

### Recommended Layout

```text
.agents/
  skills/
    skill-name/
      SKILL.md
      references/
      scripts/
skills.json
```

### Configuration Manifest (`skills.json`)

To manage and lock skills, place a `skills.json` file in the root of your project:

```json
{
  "$schema": "https://unpkg.com/skillman/skills_schema.json",
  "skills": [
    {
      "source": "Arenukvern/skill_steward",
      "commit": "ec76d3ba063543418bd8e60b8448ee81e21b0ebd",
      "skills": ["repository-governance-lifecycle", "skill-authoring-lifecycle"]
    }
  ]
}
```

- `source`: The GitHub repository source (`owner/repo`).
- `commit`: The locked commit hash for safety, reproducibility, and auditability.
- `skills`: The list of specific skills from that repository to install.

### Installation & Update Commands

After installing the CLI with `install.sh` or running from a maintainer checkout:

```bash
# Install all skills listed in project skills.json
steward install

# Install a specific skill from a repository
steward install Arenukvern/skill_steward/repository-governance-lifecycle --target cursor

# Update installed skills to their latest upstream branch refs, pinning commits in skills.json
steward update

# Validate that the local skills are present and valid
steward validate --local
```

These commands keep a project’s agent skill layer reproducible. They do not replace skills.sh discovery or `npx skills add/update` for ordinary public installs.

## Installation (end users)

```bash
# All skills
npx skills add arenukvern/skill_steward

# One skill
npx skills add arenukvern/skill_steward --skill skill-authoring-lifecycle
```

## Validation checklist

Before merging:

- [ ] `name` matches directory name and naming rules
- [ ] `description` includes trigger phrases
- [ ] No `README.md` inside skill folder (agents ignore it; use `references/` instead)
- [ ] `pnpm run validate` passes
- [ ] **T1 behavior-critical only:** `pnpm run eval` passes; `evals/cases/` updated if routing/description changed
- [ ] Skill listed in `skills.sh.json` and root `README.md`
- [ ] No secrets, API keys, or machine-specific absolute paths

## Official validator (optional)

```bash
# Python reference implementation from agentskills/agentskills
uv tool install skills-ref
skills-ref validate ./skills/my-skill
```

This repo validates skills using the `steward` CLI (or via `pnpm` scripts in development):

```bash
pnpm run validate    # all skills — structure (delegates to steward validate)
pnpm run eval        # T1 behavior-critical — evals/cases/*.yaml rules only (delegates to steward eval)
pnpm run eval:json   # machine-readable output
```
