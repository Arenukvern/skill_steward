## Implemented repairs

`action run` previously printed failure while exiting zero. It now returns the
native positive exit code (1 for rejected, blocked or abnormal outcomes).
`probe` exits zero only for `passed`; `benchmark` only for `pass`. Both text
and JSON modes preserve structured outcomes. This is a compatibility change
for automation that previously ignored failure; the global installed binary
was not replaced. A child process cannot prevent a caller from masking its
status with a pipeline: use `pipefail` or explicit exit capture.

Static evals now run all T1 skills and all skills declaring case directories.
Explicit non-T1 targets execute declared cases; T1 minimum coverage remains two.
Explicit targets without cases report `skipped` and nonzero exit. JSON exposes
status and executed/skipped coverage. The existing docs-refresh dormant case
used an unsupported enum; it was normalized to `should_not_trigger`, preserving
the prompt and assertions. The storytelling skill repeated banned hype terms
in its own warning; redundant examples were removed while preserving the rule.
Neither the pilot grader nor its acceptance conditions were changed.

## Plugin discovery repair and affected-route reruns

Validation and bundling now share one discovery function. A native Dart/MCP
package identified by `pubspec.yaml` or `mcp.json`, without a `plugin.yaml`, is
excluded from Steward wiring checks. Empty/cache-only directory residues are
also excluded. A present manifest always receives the original schema,
references, lifecycle, path and artifact-integrity checks, including beside
native metadata. Unclassified directories with visible wiring still require a
manifest; dangling manifests fail. Native package validity remains owned by its
native checks. Eight regression cases cover this boundary and bundle parity.

## Quality direction and next useful experiments

The North Star already values shorter future repair paths. A useful clarification
is to measure **maintenance burden avoided while preserving native correctness**,
not how often a skill is invoked, how many documents exist, or how many tools
Steward owns. This is a proposed emphasis, not a new maturity tier or an amended
charter.

1. **Discovery compatibility repaired locally.** Existing strict manifest
   checks and the new native/cache/mixed-directory regression cases pass.
   Extend discovery only when another real native package format requires it;
   keep validation and bundling on the same owner.
2. **Keep truthful outcomes as a release invariant.** Process failure, rejection,
   timeout, missing configuration and skipped coverage must survive JSON/text,
   shell wrappers and relevant MCP adapters. Extend existing regression tests
   when another boundary fails; do not add a separate validation framework.
3. **Measure recurring maintenance in existing adopters.** On three comparable
   episodes per selected adopter, record native success, setup/repair/operator
   effort, repeated failures and the durable change. Capture from existing
   receipts; missing values stay unknown. Retrospective adoption is the starting
   evidence, not a causal control group.
4. **Run a small held-out guidance comparison only for a concrete hypothesis.**
   Example: explicit stale-install routing reduces repair attempts without
   increasing incorrect updates. Freeze cases and oracle, counterbalance arms,
   pin client/model/skill/configuration, and include routine tasks where the
   skill should stay unused. Predeclare an acceptable overhead and practical
   benefit before running; do not select a threshold after seeing results.
5. **Use external suites selectively.** SkillsBench for skill transfer, ACES for
   a specific validation/overlap gap, AgentDojo adaptations for unauthorized
   effects plus legitimate completion, Terminal-Bench only for a demonstrated
   terminal-recovery problem. A local adaptation is not an official score.

Keep a change when it preserves correctness/safety and improves the targeted
outcome beyond its setup/maintenance cost. Narrow or retire guidance when it
adds recurring work without benefit. Retain an explicit “inconclusive” result
when the sample or instrumentation cannot answer the question. Stronger claims
require independent replay or held-out evidence; no automatic promotion follows.
