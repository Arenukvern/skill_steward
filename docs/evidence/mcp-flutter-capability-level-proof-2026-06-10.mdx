# mcp_flutter capability-level S5/H5 proof - 2026-06-10

**Status:** capability-level S5/H5 proof path · **Audience:** maintainers and agents

## Claim

`mcp_flutter` is the first Skill Steward capability-level proof target for one useful capability: hosted IntentCall dependency cutover. The ladder claim is deliberately narrow:

> A fresh agent can discover the repo contract, inspect and run the hosted-dependency gate, understand its safety and falsifier evidence, and use the result to improve one real tool surface without hidden local paths.

This is not a claim that every `mcp_flutter` workflow is H5, that WebMCP runtime dogfood is proven, that the repo is fully adopted, or that Skill Steward has broad ecosystem maturity.

## Tool improvement packet

| Field | Hosted cutover answer |
|-------|-----------------------|
| Observation | Hosted IntentCall cutover can regress if consumer pubspecs regain local `agentkit`/`intentcall` path dependencies. |
| User value | Future agents can prevent local-only success from hiding publish/consumer breakage. |
| Native owner | `mcp_flutter/tool/intentcall/check_no_path_deps.sh` and `check_no_path_deps_test.sh`. |

| Positive proof | `steward action inspect fmt.check.intentcall-hosted-deps --json`, quick probe, and strict benchmark pass on current dependency state. |
| Promotion criteria | Native gate exists, falsifier exists, action is inspectable, quick probe includes it, strict benchmark passes, evidence note states non-claims. |
| Educational note | Prefer promoting deterministic native gates that prevent real repo maintenance failures; keep runtime-heavy dogfood as a separate proof path. |

## Required verification commands

Run in `/Users/anton/mcp/mcp_flutter` or the target checkout root:

```bash
steward doctor --json
steward actions list --json
steward action inspect fmt.check.intentcall-hosted-deps --json
steward probe --profile quick --json
bash tool/intentcall/check_no_path_deps_test.sh
make check-contracts
steward benchmark --scenario mcp_flutter.intentcall-hosted-cutover --strict --output .steward/benchmark-summaries/mcp_flutter.intentcall-hosted-cutover.strict.json --json
```

Reusable docs must use the released `steward` executable, Skill Steward setup action, `cd packages/steward_cli && dart run :steward`, or `dart pub global activate --source path packages/steward_cli`. Raw `dart --packages=...` and machine-specific `/Users/...` command paths are provenance only.

## Fresh-agent exercise

A separate fresh-agent exercise in `mcp_flutter` used declared surfaces first and ran `steward doctor`, `actions list`, `action inspect`, `probe`, the hosted-cutover falsifier test, and `git status --short`. It reported the action discoverable, bounded, quick-probe eligible, and live-passing. The exercise also found that owner/risk/validation metadata should be visible from the inspected action surface; `mcp_flutter/steward.yaml` now records those fields under the action evidence.

## What remains open

- WebMCP runtime dogfood is separate from this hosted-dependency gate.
- Skill metadata/source warnings in `mcp_flutter make check-contracts` are backlog unless they become gate failures.
- `source.commit` remains the subject commit in benchmark summaries; it is not remote-equivalence proof.
- The next adoption should reuse the [adoption-run/v2 template](adoption-run-v2-template) and prove a different useful capability before claiming broader ecosystem maturity.
