# Stewardship Protocol Adopter Plan

## Scope

This is a plan for future adopter work. It is not current proof.

## mcp_flutter

Root steward only.

Falsifier tasks:

1. Tool surface: registry still matches canonical `fmt_*` expected surface.
2. Version train: package, plugin, runtime metadata, and generated assets agree.
3. Init surface: `flutter-mcp-toolkit init` produces agent manifests without stale paths.
4. IntentCall cutover: no local `intentcall_*` path dependencies; consumer docs only.
5. Warm runtime: discover app, capture UI, inspect widget, and enter text through shared CLI/MCP semantics.

Do not persist:

- Canonical IntentCall architecture.
- Old implemented plans or closures.
- Raw runtime logs or screenshots unless redacted into evidence.
- Absolute local runner hacks.
- Dirty benchmark summaries as ready proof.

## ecsly

Root steward plus temporary sub-steward lenses.

Sub-steward lenses:

- Core ECS.
- Plugins.
- Prototypes.
- Graphics/native.
- Tooling/harness.

Falsifier tasks:

1. Root observe: `ecsly observe -p spark_physics_ecs --json` reports toolchain, MCP binding, verify pipeline, and GitNexus/status hints.
2. Core ECS: stale entity IDs, deferred command flush, deterministic fixed-step loop, and no hot-loop heap-object regression.
3. Plugin boundary: resources remain data-only; non-Flutter plugins do not leak Flutter dependencies.
4. Prototype T1: dry-run verify pipeline proves replay/snapshot fixtures exist for `spark_physics_ecs`.
5. Graphics/native: capture hints, stale dylib detection, and one golden-frame or parity artifact for WGPU/platform-view paths.

Do not persist:

- Every prototype experiment as root doctrine.
- Build or generated artifacts as evidence.
- Raw playtest media.
- Broad `fs_read: ["."]` contracts.
- One-off plans after extraction.

## Current Proof Status

This plan does not prove either adopter. Fresh runs must use each repo's current dirty state and local contract.

## Non-claims

- This does not prove `proven_repo_steward`.
- This does not prove either adopter is harness-ready.
- This does not authorize sub-stewards before root steward plus temporary lenses proves insufficient.
