# Steward schemas

Language-neutral JSON Schema artifacts for Steward contracts.

These schemas are companion contracts for agents, repo maintainers, and non-Dart harnesses. The Dart validator remains the executable gate, but these files make the data shapes portable.

| Contract | Schema |
|---|---|
| `steward.yaml` v1 | [steward-v1.schema.json](steward-v1.schema.json) |
| Scenario manifest | [scenario-manifest-v1.schema.json](scenario-manifest-v1.schema.json) |
| Plugin manifest | [plugin-manifest-v1.schema.json](plugin-manifest-v1.schema.json) |
| Plugin bundle | [plugin-bundle-v1.schema.json](plugin-bundle-v1.schema.json) |
| Plugin bundle index | [plugin-bundle-index-v1.schema.json](plugin-bundle-index-v1.schema.json) |
| Doctor output | [doctor-v1.schema.json](doctor-v1.schema.json) |
| Observation record | [observation-v1.schema.json](observation-v1.schema.json) |
| Unknown case record | [unknown-case-v1.schema.json](unknown-case-v1.schema.json) |
| Action candidate record | [action-candidate-v1.schema.json](action-candidate-v1.schema.json) |
| Benchmark summary | [benchmark-summary-v1.schema.json](benchmark-summary-v1.schema.json) |

Schema policy:

- Required fields match the current v1 hard-cut validator.
- Product-specific extension fields are allowed unless they would hide unsafe execution or provenance.
- Runtime payload schemas describe compact summaries, not raw logs, screenshots, or product artifacts.
