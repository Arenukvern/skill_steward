# Skill Steward — North Star

**Status:** active · **Audience:** humans and agents

## What we are

**Skill Steward** is an **engineering stewardship meta-layer** for the Agent Skills ecosystem: small **skills**, **plugins**, schemas, and validation patterns that help teams manage other skills, document decisions, enforce quality gates, package agent workflows, and grow repo-local harnesses without turning this repo into a product runtime.

We are **not** a general domain skill catalog (React, Flutter, cloud recipes live elsewhere). We are **not** a skill package manager ([Skillkit](https://github.com/rohitg00/skillkit), [skills.sh](https://skills.sh)).

Sibling work: Product harness repositories (such as product-level MCP/CLI toolkits) own runtime/framework harnesses. Skill Steward owns structural guidance, meta-skills, validation, packaging patterns, and documentation patterns. Principles: [credo](https://dev.to/arenukvern/my-principles-at-work-credo-182c).

## What we own

| Own | Do not own |
|-----|------------|
| Meta-skills (`skills/`) | Domain/framework instruction packs |
| Skill validation (`pnpm run validate`, `steward` CLI) | Product MCP servers and framework wrappers |
| Doc patterns (FAQ, ADR, docs.page lattice) | Finished plan files as permanent docs |
| Plugin manifests (`plugins/`) when wired | Copy-pasted API docs of other products |
| Harness **culture** skill (how to build CLI/MCP harnesses) | Executable app/runtime code (except our meta CLI) |

## Stewardship Pillars

Harness engineering is one pillar, not the umbrella.

| Pillar | Owns |
|--------|------|
| Governance | Charter, boundaries, ethics, ADRs, plan hygiene |
| Knowledge | FAQ split, docs maps, source citations, durable provenance |
| Skill lifecycle | Skill authoring, packaging, installability, marketplace readiness |
| Quality gates | Validation, Tier-1 skill evals, prompt suites, bounded improvement loops |
| Harness engineering | CLI/MCP/core parity, repo-local contracts, dogfood feedback loops |
| Release legibility | Changelog, versioning, artifact provenance, release impact |
| Review and handoff | MoE critique, multi-agent handoff, PR review patterns |
| Strategic alignment | Vision vs implementation fit, usage evidence, future-fit analysis, falsifiers |
| Security posture | Secret hygiene, action risk classes, provenance, supply-chain review |
| Org patterns | Repo archetypes, ownership, operating model, agent routing |

## How we ship value

1. **`npx skills add arenukvern/skill_steward`** — portable `SKILL.md` packages.
2. **Docs as system of record** — [docs.page](https://docs.page/arenukvern/skill_steward) from `docs/` + `docs.json`; `AGENTS.md` is the agent map only.
3. **Mechanical gates** — CI validates skills; contributors run `pnpm run validate`.
4. **Plan hygiene (any format)** — use any planning tool; when work is done, [extract into ADR/FAQ/code/harness](start_here/executable-plans), then **remove** stale plan files from the repo.

## Boundaries (non‑negotiable)

- One clear outcome per skill; `SKILL.md` stays lean.
- Skills in `skills/`; wiring in `plugins/`; templates in `templates/` (not installable).
- **Behavior SSOT is code** — docs link inward; they do not paraphrase implementations.
- New strategic **why** → ADR; standing **why** → [DESIGN_FAQ.mdx](DESIGN_FAQ); **how** → [DX_FAQ.mdx](DX_FAQ).
- **Ethical governance model** — use [`repository-governance-lifecycle`](https://github.com/arenukvern/skill_steward/blob/main/skills/repository-governance-lifecycle/SKILL.md) and its charter references to bootstrap, audit, and refine the credo and design constraints for this repo.

## Success looks like

- Agents and humans can install Skill Steward meta-skills without confusion about scope.
- Product repos adopt our stewardship patterns via installed skills: governance, FAQ/ADR shape, quality gates, release legibility, and local harness feedback loops.
- The repo stays small enough to maintain; stale plans do not accumulate.
