# Concept: distribution boundaries

Skill Steward separates mission from delivery surface.

| Layer | Purpose | Boundary |
|-------|---------|----------|
| Engineering Stewardship | Structural governance and quality for repos | Applies to apps, libraries, tools, plugins, harnesses, and meta repos |
| Agent Skills | Portable agent procedures | Does not contain full domain/runtime knowledge |
| `npx skills` / skills.sh | Public install and discovery | Does not validate repo-local contracts |
| `steward install/update` | Deterministic repo-local skill registration | Does not replace public package managers |
| `steward doctor/actions/probe/benchmark` | Machine-readable contract proof | Does not bless raw shell automation without review |
| `install.sh` / setup action / declarative tool managers / `dart pub global activate` / `dart run :steward` | Portable CLI invocation paths | Does not justify publishing absolute maintainer paths or adopter-local runner scripts as reusable commands |
| Product harnesses | Runtime/framework visibility and actuation | Owned by product/harness repos, not Skill Steward |

The practical rule: broaden the stewardship audience, but keep this repo's artifacts small, structural, and reusable.

Invocation details: [Portable Steward invocation](portable-steward-invocation).

## Adoption check

Use this concept when a change blurs delivery surfaces. Minimum artifact: name the layer that owns the behavior and the layer that only points to it.

Do not use this concept to justify adding product/domain runtime logic to Skill Steward.
