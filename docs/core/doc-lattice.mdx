# Concept: docs lattice

The docs lattice keeps different kinds of truth from collapsing into one giant README.

| Layer | Owns | Canonical file in Skill Steward |
|-------|------|---------------------------------|
| Charter | Scope, boundaries, success, maturity | `docs/NORTH_STAR.mdx` |
| Why | Standing decisions and rationale | `docs/DESIGN_FAQ.mdx`, `docs/decisions/` |
| How | Commands and contributor workflows | `docs/DX_FAQ.mdx`, `CONTRIBUTING.md` |
| Spec | Normative rules | `docs/STANDARDS.mdx`, `docs/repo-quality-contracts.mdx` |
| Map | Where to go first | `AGENTS.md`, `docs/start_here/docs_map.mdx` |
| Behavior | Runtime truth | Code, schemas, validators, tests |
| Procedure | Agent workflow | `skills/*/SKILL.md` |

When a topic appears in multiple places, one page must be the canonical owner and the others should link to it.

## Adoption check

Use this concept when a reader or agent could update the wrong document. Minimum artifact: one canonical owner plus links from every secondary mention.

Do not duplicate implementation behavior in prose when code, schemas, tests, or generated artifacts already own the truth.
